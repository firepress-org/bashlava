# Overview

## Corpus Type

`code-repo` with English as the dominant language. The executable source is stronger than the docs: when docs and code disagree, prefer L2 in `bashlava.sh` and the sourced helper scripts.

## Navigation Strategy

Start with `README.md` only for orientation. For actual behavior, go straight to `bashlava.sh`, then follow the matching note in `docs/` if the command prints a next-step prompt or help text. Read `components/` when the question is about aliases, namespace listing, examples, or utility experiments rather than the main release-flow commands.

## Retrieval Routes

- If the task is "what does command `x` do?", read `bashlava.sh` first, then the matching file in `docs/` if one exists such as `docs/fct_c_next.md` or `docs/next_move_fct_edge.md`.
- If the task is "what commands exist?", read `docs/help.md` for the fast list, then confirm in `bashlava.sh`.
- If the task is about aliases like `e`, `c`, `m`, `sq`, or `sv`, read `components/alias.sh` and then jump to the matching function in `bashlava.sh`.
- If the task is about namespace browsing or "show me the available function groups", read `components/Show_Fct_Category_Filter.sh`.
- If the task is about shared shell mechanics rather than Git workflow, read `.bashcheck.sh` directly.
- If the task mentions GitHub CLI upstream/origin oddities, use `docs/debug_upstream.md` as a secondary note after checking the relevant command in `bashlava.sh`.

## Semantic Entry Points

- `e`, `edge`, `dev branch` -> branch creation flow in `bashlava.sh`, then `docs/next_move_fct_edge.md`.
- `c`, `commit`, `next move after commit` -> `bashlava.sh`, then `docs/fct_c_next.md`.
- `pr`, `mrg`, `ci`, `release`, `tag`, `version` -> command implementations in `bashlava.sh`; prompt docs live under `docs/next_move_fct_*.md`.
- `h`, `help`, `command list` -> `docs/help.md`.
- `gc`, `git-crypt` -> `docs/help.md` and `docs/help_gitcrypt.md`.
- `show`, `s`, `function categories` -> `components/Show_Fct_Category_Filter.sh` and `docs/prompt_show_fct.md`.

## Gaps and Cautions

- `README.md` and `docs/README_wip.md` both signal incomplete or stale documentation; use them for orientation only.
- `components/utilities.sh` contains draft or project-specific utility ideas; do not assume those functions are part of the stable CLI.
- `REQUIREMENTS.md` is a planning scratchpad, not an authoritative roadmap.
